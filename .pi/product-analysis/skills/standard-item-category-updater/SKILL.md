# 품목분석 영역
# 실제 실행 코드: services/product/



## 목적 및 범위
- 기존 표준 품목에 할당된 카테고리를 변경하거나, 신규 표준 품목에 카테고리를 연결한다.
- **포함**: 품목-카테고리 매핑 갱신, 기존 연결 해제, 충돌 검사, 변경 이력 기록
- **제외**: 표준 품목 자체 등록/삭제, 카테고리 등록/삭제

## 작업 절차
1. 표준 품목-카테고리 연결 갱신 요청을 입력받는다.
2. 대상 표준 품목이 허용 목록에 존재하는지 확인한다.
3. 대상 카테고리가 허용 목록에 존재하는지 확인한다.
4. 기존 연결 관계가 있으면 새 연결로 덮어쓴다.
5. 동일 표준 품목에 서로 다른 카테고리가 중복 연결된 경우 경고하고 최신값으로 정리한다.
6. 변경 전후 연결 관계를 이력에 기록한다.
7. 갱신된 연결 테이블을 저장한다.

## 사용 규칙 및 제약 사항
- 표준 품목과 카테고리 모두 허용 목록에 존재해야 갱신이 가능하다.
- 하나의 표준 품목에 여러 카테고리를 허용하는 정책인 경우, 중복 연결을 충돌로 보지 않을 수 있다.
- 연결 해제 시 “카테고리 미지정” 상태로 Marks하며, 후속 분류에서는 재할당을 유도한다.
- 변경 이력은 표준 품목명, 이전 카테고리, 신규 카테고리, 변경 시각을 포함한다.
- 갱신 결과는 즉시 `category-validator` 및 `classification-confidence-calculator`에 반영되어야 한다.
- 연결 테이블 백업은 매 변경 시 자동 생성한다.

## 템플릿
입력:
- `mapping_update_list`: {standard_item, category, action: "assign"|"unassign"}[]
- `current_item_category_map`: 현재 품목-카테고리 연결 테이블

출력:
- `updated_item_category_map`: 갱신된 연결 테이블
- `update_log`: {standard_item, old_category, new_category, action, timestamp}[]
- `warnings`: 충돌 또는 예외 경고 목록

실행 예시:
1. “코카콜라 355ml” → “음료” 재할당
2. 이전 연결 “생수” 해제
3. 변경 이력 기록
4. 갱신된 매핑 저장
