---

## 목적 및 범위
- 사용자의 수정 결과를 바탕으로 기존 매핑 사전을 갱신하고, 변경된 매핑을 이후 자동 분류에 재사용할 수 있도록 한다.
- **포함**: 매핑 사전 로드, 기존 매핑 갱신/추가, 충돌 검사, 변경 이력 기록
- **제외**: 표준 품목/카테고리 신규 등록, 승인 이력 관리

## 작업 절차
1. 수정된 품목명-표준 품목 매핑 결과 목록을 입력받는다.
2. 기존 분류 사전을 로드한다.
3. 각 수정 건에 대해 기존 매핑 존재 여부를 확인한다.
4. 기존 매핑이 있으면 새 값으로 덮어쓰고, 없으면 신규 엔트리를 추가한다.
5. 동일 원본 품목명에 대해 서로 다른 표준 품목이 입력되면 충돌로 표시하고 사용자에게 알린다.
6. 변경된 엔트리와 삭제/수정 전후 값을 이력에 기록한다.
7. 갱신된 분류 사전을 저장소에 영구 반영한다.

## 사용 규칙 및 제약 사항
- 매핑 사전 갱신은 승인 처리 후에만 수행한다.
- 충돌 발생 시 자동 병합하지 않고, 사용자 수동 해결을 기다린다.
- 기존 매핑을 삭제할 경우 반드시 삭제 사유 필드를 함께 기록한다.
- 변경 전 값은 반드시 보존하며, 복구 가능하도록 버전 관리한다.
- 갱신 후 즉시 동일 품목에 대한 후속 분류에 변경된 매핑이 적용되어야 한다.
- 매핑 사전 파일 손상 방지를 위해 저장 전 사본 백업을 생성한다.

## 템플릿
입력:
- `existing_mapping_dict`: 기존 매핑 사전
- `update_list`: {raw_name, new_standard_item, action: "update"|"insert"}[]
- `conflict_resolution_mode`: "manual" | "latest_wins"

출력:
- `updated_mapping_dict`: 갱신된 매핑 사전
- `change_log`: {raw_name, old_value, new_value, action, timestamp}[]
- `conflicts`: 충돌 발생 엔트리 목록

실행 예시:
1. “콜라355” → 기존 매핑 존재 → “코카콜라 355ml”로 수정
2. “펩시제로 0kcal” → 신규 등록
3. 충돌 없음 → 정상 갱신
4. 변경 이력 저장
