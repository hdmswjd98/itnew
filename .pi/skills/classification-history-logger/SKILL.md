## 목적 및 범위
- 시스템의 모든 분류 관련 상태 변경 이벤트를 시간순 이력 형태로 보존하여, 사후 추적·감사·재현에 활용한다.
- **포함**: 이벤트 수신, 타임스탬프 부여, 이력 직렬화, 이력 저장소 기록, 이력 조회 인터페이스 제공
- **제외**: 분류 결과 자체 생성, 통계 계산, 대시보드 렌더링

## 작업 절차
1. 분류 파이프라인 각 단계에서 발생한 이벤트를 입력받는다.
2. 각 이벤트에 고유 ID, 발생 시각, 이벤트 유형, 대상 행/품목, 변경 전후 값을 부착한다.
3. 이벤트 데이터를 JSON Lines 형식으로 직렬화한다.
4. 이력 저장소에 순차 기록한다.
5. 동일 대상에 대한 중복 이벤트는 최신 값으로 병합하지 않고, 별도 이벤트로 보존한다.
6. 이력 조회 요청 시 기간·품목·이벤드 유형으로 필터링하여 반환한다.

## 사용 규칙 및 제약 사항
- 이력은 삭제·변조가 불가능한 append-only 방식으로 저장한다.
- 모든 파이프라인 상태 변경은 반드시 이력으로 남아야 한다.
- 이벤트 스키마는 버전 관리해야 하며, 스키마 변경 시 이전 버전 호환을 유지한다.
- 이력 저장 용량은 정책 기반 회전(예: 90일 보관, 수동 아카이브)을 지원해야 한다.
- 민감 정보(사용자 식별정보 등)는 마스킹 처리 후 저장할 수 있다.
- 이력 조회 응답 시간은 대량 데이터 대비 페이징을 지원해야 한다.

## 템플릿
입력:
- `event_stream`: {event_type, row_id, item, before, after, actor}[]
- `storage_path`: 이력 저장소 경로

출력:
- `logged_events`: 저장된 이벤트 목록
- `history_index`: {latest_event_id, total_count, storage_path}
- `query_result`: (조회 시) 필터링된 이력 목록

실행 예시:
1. 승인 이벤트 수신
2. {event_type: "approval", row_id: 42, before: "review", after: "approved", timestamp: ...}
3. 이력 저장소에 직렬화 기록
4. 조회 시 기간 필터 적용 가능
