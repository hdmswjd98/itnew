## 목적
파이프라인 전체의 중간 산출물을 하나의 완성된 Markdown 보고서로 조립한다.

## 사용 시점
validation-suite 검증 완료 후 (최종 단계)

## 보고서 구조 (spec.md 기준 11개 섹션)
1. 조회 기간 및 분석 조건
2. 입력 데이터 검증 결과
3. 고객군별 고객 수 및 비율
4. 고객별 이용 지표
5. 신규·재이용·이탈 위험 고객 분류 결과
6. 이탈 위험 고객 목록 및 분류 근거
7. 고객군별 지역 특성
8. 고객군별 업종 특성
9. 고객군별 품목 주문 횟수·주문 금액·비율 및 상위 품목
10. AI 분석 요약
11. 분석 결과 검증 결과

## 조립 규칙
- 각 섹션은 spec.md 의 출력 형식 테이블 템플릿을 정확히 따름
- 금액: "N,NNN,NNN원" 형식
- 날짜: "YYYY-MM-DD" 형식
- 비율: 소수점 첫째자리까지 표시 (예: 42.9%)
- 이탈 위험률: 위험 등급 고객 수 ÷ 전체 주문 3회 이상 분석 대상 고객 수 × 100
- 고객별 이탈 표: 주문 횟수, 최근 주문일, 평균 이용 주기, 경과일, 경과 비율, 등급, 판단 근거 포함
- AI 요약: 5문장 이내, 데이터에 근거한 내용만
- 검증 결과: 통과/실패와 원인을 명시

## 실행 방법
```bash
python .pi/skills/dashboard-formatter/scripts/build_report.py
```

## 출력
- customer_analysis_result.md (최종 보고서)

## 제약
- spec.md 의 섹션 순서를 임의로 변경하지 않음
- 입력 데이터에 없는 값을 임의로 생성하지 않음
- 모든 결과는 한국어
- 동일한 입력 데이터에 대해 항상 동일한 보고서가 생성되어야 함
