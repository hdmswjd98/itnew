# 품목분석 영역
# 실제 실행 코드: services/product/



## 목적 및 범위
- 표준 품목 검증과 동일한 방식으로, 추천 카테고리의 유효성을 확인하여 분류 체계의 일관성을 유지한다.
- **포함**: 허용 카테고리 목록 로드, 추천 카테고리 존재 여부 검사, 오타 근사 탐색, 검증 결과 기록
- **제외**: 표준 품목 검증, 신뢰도 계산, 분류 사전 갱신

## 작업 절차
1. 파싱된 응답 데이터셋과 허용 카테고리 목록 경로를 입력받는다.
2. 허용 카테고리 목록을 메모리에 로드한다.
3. 각 AI 추천 카테고리가 허용 목록에 존재하는지 확인한다.
4. 존재하지 않는 경우 문자열 유사도를 기준으로 근접 허용 카테고리를 탐색한다.
5. 임계치 이상 유사 항목이 있으면 “유사 매칭”으로 기록한다.
6. 전혀 부합하지 않으면 “검증 실패”로 표시하고, 이후 `review-target-selector`로 전달한다.
7. 검증 결과 배열과 실패 품목 목록을 반환한다.

## 사용 규칙 및 제약 사항
- 허용 카테고리 목록은 분류 체계 변경 시에만 갱신한다.
- 유사도 임계치는 표준 품목 검증과 동일하게 설정 가능하며, 기본값은 0.85다.
- 검증 실패 카테고리는 자동 할당하지 않고, 사용자 검토 대상으로 넘긴다.
- 카테고리가 빈 문자열이거나 null인 경우 “미지정”으로 표시하고, 자동 보완을 시도하지 않는다.
- 허용 목록에 대소문자 변형이 있어도 동일 항목으로 간주한다(예: “음료” = “음료”).
- 검증 통과 여부를 신뢰도 계산에 참고하되, 신뢰도 값을 직접 산출하지는 않는다.

## 템플릿
입력:
- `parsed_responses`: 파싱된 응답 데이터셋
- `allowed_categories_path`: 허용 카테고리 목록 파일 경로
- `similarity_threshold`: 유사 매칭 임계치(기본 0.85)

출력:
- `validated_responses`: {row_id, raw_name, recommended_category, validation_status, matched_category, similarity_score}[]
- `failed_items`: 검증 실패 품목 목록
- `category_suggestion_log`: 유사 매칭 추천 로그

실행 예시:
1. 추천 카테고리: “음료” → 허용 목록에 존재 → pass
2. 추천: “음료수” → 유사도 0.88 → 유사 매칭 → “음료”로 보정 제안
3. 추천: “면세점” → 허용 목록 없음 → fail → 검토 대상
